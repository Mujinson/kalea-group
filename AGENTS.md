
- Email campaigns live in dedicated tables (email_campaigns, email_campaign_recipients, email_templates, email_suppressions, email_events) and edge functions campaign-sender / campaign-unsubscribe / resend-webhook; working-day logic lives in supabase/functions/_shared/workdays.ts (tested with bun test). Why: keeps campaigns separate from lead_automations, which lead-automation already uses.
- Revenue cash source selection lives in src/lib/revenueSources.ts with regression tests: count all installments for cash, standalone invoices separately, and only unlinked paid installments as synthetic billed rows. Why: prevents missing invoice-linked cash and double-counting invoices.
- Quote technical sheets are stored in quote_data.technicalAttachments; user uploads use private quote-scoped storage paths. Both desktop and mobile invoke the editor's export, merging PDFs via src/lib/mergeQuotePdfs.ts. Why: preserves attachment persistence, access control, and identical ordered output across devices.
- Crew/travel costs: formulas in src/lib/crewCosts.ts (tested), quote estimate in quote_data.contabilita.crewTrip, defaults in crew_cost_settings, real per-day costs in site_daily_costs; routing via edge function route-cost (Google Routes, admin-only). Why: one formula shared by quote, site and dashboard.
- Company profitability uses companyProfit.ts for net calculations, quote accounting snapshots for historical estimates, and admin-only profit cost allocations/closures/payroll records for reconciliation; period actuals and lifetime won-job forecasts stay separate. Why: prevents double-counting documents, estimates, sales and payroll, while exposing incomplete costs.
